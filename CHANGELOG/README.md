# CHANGELOG

按大版本分树（`v1/`、`v2/`、`v3/`），每个版本一个目录，目录内固定为一份 `CHANGELOG.md`。

- 目录名与 Git 标签一致（标签 `v3.0.1` ↔ 目录 `CHANGELOG/v3/v3.0.1/`）；大版本归属以本目录的树为准，而不是标签号。
- 文件内容会被 CI 直接用作 GitHub Release 正文，所以只写用户需要看的内容。
- `scripts/ReleaseHistory/parse_changelog.py` 只扫描 `CHANGELOG/**/CHANGELOG.md`，本 README 等其它文件不参与解析。

## 正式版 note 模板

所有正式版（无预发布后缀）统一使用下面这段 `note`，**只替换版本号**，其余文字保持一致：

```markdown
> [!note]
>
> # vX.Y.Z 正式版发布
>
> 感谢您一路以来的等待与支持，**vX.Y.Z 正式版**现已发布，可直接用于日常教学等正式场景。
>
> **📣 我们需要您**：如果发现任何 Bug，或有功能改进建议，欢迎随时前往 **GitHub Issues** 提交反馈。
>
> 感谢您陪伴 SecRandom 一路走到这里！
```

## Beta note 模板

Beta 同样用 `> [!caution]`，固定为：

```markdown
> [!caution]
>
> # 抢先体验 Beta 版
>
> 您正在使用我们的最新功能预览版。为了在正式版中给您带来更完美的体验，我们需要您的帮助与反馈。
>
> **⚠️ 风险提示**：此版本尚在打磨中，可能存在偶发异常或未知问题，**请务必避免用于关键业务或生产环境**。
>
> **📣 我们需要您**：如果发现任何 Bug，或有功能改进建议，欢迎随时前往 **GitHub Issues** 提交反馈。
>
> 感谢您成为我们的首批体验官！
```

## Alpha note 模板

Alpha 用 `> [!caution]` 明确提示不要在生产环境使用，固定为：

```markdown
> [!caution]
>
> # 警告！当前版本为 Alpha 版本，请勿在生产环境使用
>
> **⚠️ 警告**：当前版本为 **Alpha 版本**，**请勿在生产环境使用**。当前版本可能存在未知 Bug，仅供用户体验。使用中如遇问题，欢迎前往 **GitHub Issues** 反馈！
```

早期阶段需要额外交代（例如「早期预览，功能未经完整测试」）时，在这段基础上补段落，可参考 `v3/v3.0.0-alpha.2/`。

Alpha / Beta 的版本号只出现在 note 下方的 `# <版本号> - <代号>` 标题里，所以这两段 note 本身不需要按版本改动。

正文其余部分沿用现有结构：顶部横幅图片、`# <版本号> - <代号>` 标题、`## 🚀 主要更新` / `## 💡 功能优化` / `## 🐛 修复问题` 三个板块（无内容写「无」），需要时补 `## 🙏 贡献者`，结尾固定为 `---` 加「💝 **感谢所有贡献者为 SecRandom 项目付出的努力！**」。
