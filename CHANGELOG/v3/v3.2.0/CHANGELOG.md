# v3.2.0 - Nonomi (十六夜野宫)

## 🚀 主要更新

- 新增 **历史记录组**：同一个名单的历史可以被拆成互不干扰的若干组（例如「课堂提问」和「抽奖」），在点名、抽奖主页面选一个组即可把抽取锁定到该组——权重只参考这一组里已有的记录，本次记录也只写进这一组
- 新增 **组管理**：在「设置 → 历史记录 → 历史记录管理」里可以新建、改名、删除记录组；删除只会把该组记录移回默认组，不会删除任何一条历史
- 新增 **历史页的记录组列与筛选**，并支持把已有记录「移到另一组」，用来修复选错组的记录或把旧记录归档
- 新增 **首页「默认记录组」选项**：点名页、抽奖页的记录组下拉里，第一项是「默认记录组」，选它表示只按未分组的记录计算权重——已经分到别的组的记录不会混进来；主页面只保留这一个下拉，不再有锁定提示或取消按钮
- 新增 **导出包含记录组列**：导出的 XLSX/CSV 明细多一列记录组，便于按用途核对
- 新增 **闪抽默认记录组**：闪抽没有自己的选择器，改为在「抽取设置 → 闪抽」里设一个默认组，之后每次闪抽都锁在该组（悬浮窗上会有一行提示说明当前锁定到哪个组）
- 新增 **点名/抽奖的持久化默认记录组**：在两页各自「抽取设置」里可以指定下次打开时组下拉默认落在哪一组——下拉本身仍然只是本次会话的临时选择，改动设置里的默认组才会影响下一次打开；选「默认记录组」表示只算未分组的记录，与「不分组（全部历史）」不是一回事
- 新增 **默认组失效回落**：设置里的组被删除或改名后，下一次抽取自动回落到「默认记录组」（删除组只会把它的记录移回默认组），闪抽提示里还会多一句说明原组已不存在
- 新增 **证明声明整理范围**：可验证抽奖的证明里会写明本次权重用的是哪一个范围的历史（全局 / 课程 / 记录组 / 课程加记录组），验证端据此按同样的范围重放；证明引擎版本随之升到 3.4.0

## 💡 功能优化

- 优化 **课程过滤与记录组可以同时使用**：开了课程联动过滤时，两个维度取交集，互不覆盖
- 优化 **抽奖页的分配学生权重**：抽奖页选择记录组后，分配给奖品的学生也按该组的历史计算权重
- 优化 **重复抽取上限按记录组独立计数**：临时记录里的「已抽中次数」现在按记录组分开存（不分组、默认组、每个具名组各一份），换组不会再把上一组的计数带过来；改名组会把计数合并到新名字，删除组会把计数并入默认组。升级前的历史计数无法判断属于哪个组，统一归到「不分组」那一份，按组计数从零开始
- 优化 **历史记录改用轻量数据库存储**：每个名单/奖池的历史现在是一个小的 SQLite 数据库（`data/history/**/*.srhdb`），保存只写本次变动的成员与记录，不再每次把整份历史重新序列化。以 60 人 × 300 轮（1.8 万条记录）为例：整份保存从约 112 ms 降到 35 ms、一次抽取的增量保存约 37 ms，文件体积从 9.4 MB 降到 1.9 MB，读取也略快；备份、云备份、还原与导入导出仍然按整个 `data/history` 目录处理，不需要额外操作
- 新增 **历史记录无感迁移**：升级后第一次读取某个名单/奖池时，旧的历史 JSON 会自动导入新数据库，原文件改名成 `*.json.migrated` 留作一次性回滚副本（不再参与任何 JSON 读取）。不需要手动迁移，恢复旧版备份包（里面是 JSON）后同样会被自动导入
- 注意 **降级需要手动换回 JSON**：旧版本只认识历史 JSON，回退到旧版本前请把 `data/history/**/*.json.migrated` 改名回 `*.json`，否则旧版本看不到这些名单的历史记录

## 🐛 修复问题

- 修复 **便携版开机启动项指向版本文件夹**：便携包的自启动与 `secrandom://` 协议注册现在指向包根目录的 `SecRandomLauncher`，而不是 `app-*` 版本目录里的 `SecRandom.Desktop.exe`；更新替换版本目录后开机启动不再失效，也无需重新设置，已有的旧条目会在下次启动时自动改写
